## 3. 已达成的重要里程碑

### 3.1 修补链端到端（真样本，魅族 21 官方 boot.img）
- 引擎 `rc=0`，输出**等长** 33,892,864 B（kernel 段）
- `magiskboot` 重打包 → **100,663,296 B = 分区大小**
- **AVB 零触碰**：`RB1~RB6 6/6 PASS`（AVBf footer + 内嵌 vbmeta 2,496 B 逐字节保留）
- 三方交叉校验 kernel sha256 一致：`magiskboot` / 自研 bootimg / 独立解析 = `4d445384…`
- **T-12 防线**（最隐蔽失败模式）：`cp kernel.patched kernel` + repack 后回读 kernel，**双条件断言**（== patched 且 != orig），不满足则中止且**不导出**

### 3.2 AVB 策略定论（推翻早期假设）
- 三家实现（MEIZU21GKI / KernelSU / KernelPatch）**均不处理 AVB 密码学**，靠**已解锁 bootloader 跳过验证**开机
- 魅族 21：`vbmeta.img` 对 boot 仅 **Chain Partition descriptor**（SHA256_RSA4096），boot 的 hash descriptor 在 **boot.img 内嵌 vbmeta**；无魅族私钥不可能重签
- **`--disable-verification` 才是清数据元凶**，必须禁用
- 正确刷入：`fastboot flash boot <patched>.img`（双槽 `--slot=all`）→ `fastboot reboot`；**禁止任何 vbmeta 操作**

### 3.3 打包工具链
- 主路径 = **magiskboot**（Magisk v31.1 官方 APK 内 `lib/arm64-v8a/libmagiskboot.so`，988,984 B，sha256 `97e9ec75…`）
- **禁用 Android.Image.Kitchen**（不支持 Linux 6.0+）与非官方 Windows 版
- 自研 bootimg 保留作交叉校验/回退

### 3.4 许可（人类裁定 AGPL-3.0）
- `LICENSE` = AGPL-3.0 全文；`LICENSES.md` = **SK 上游 15 文件逐字节相同的清单 + sha256 指纹 + 复现命令**，明确「原作者保留所有权利」「不改动其许可状态」「AGPL 不适用于该部分」
- `NOTICE` = 第三方（magiskboot GPL-3.0 / asmjit Zlib / capstone BSD-3 / cJSON MIT / AndroidX·Compose·miuix Apache-2.0）+ apd 115 个 Rust 依赖合规
- **APK 内同样随包**：`assets/NOTICE` + `assets/licenses/{LICENSE, AGPL-3.0.txt, GPL-3.0.txt, NOTICE}`
- **防漂移**：`check_licenses.py` + `licenses.yml` —— 改动上游文件即 CI 红

### 3.5 可复现构建
- `app/native.lock.json` 锁定三件 native 的 `run_id + sha256 + size`；CI 按 run_id 精确下载并校验，**不再浮动 latest**

## 6.6 协作方式（重要，避免重复踩坑）

- **分支纪律**：只推 `v2`；`main` 为旧 APatch 代码，不得作为测试对象。
- **构建纪律**：禁止本地编译交付物，一律 GitHub Actions。
- **许可文件归属**：根 `LICENSE` / `LICENSES.md` / `NOTICE` 由 **Lead 独占维护**，成员不得修改。
- **无写权限成员**：用 `git format-patch` 导出到 `dist/<用途>/` 并通知 Lead 代推（已发生两次：v1.1.2、v1.1.3）。
- **native 版本**：由 `app/native.lock.json` 锁定 `run_id + sha256 + size`，CI 精确下载并校验；升级必须改 lock 单独 commit。
- **artifact 口径**：只认 CI artifacts；下载需先取 302 `redirect_url` 再 curl 签名 URL（`-L` 直连会 `curl(56)`）。
- **体积口径**：区分「artifact zip 大小」与「未压缩 ELF 大小」，报告时必须注明。

### 6.7 当前唯一功能缺口（明早优先）

**自启链未闭合**：客户端已能向 ramdisk 注入 `init.sproot.rc` + `import`，但 rc 里**只有建目录、没有 apd daemon 启动行** → **AP 守护开机不会自启**（模块/授权开机后不可用）。

- 原因：`apd daemon` 需要 `--superkey-file`，而**密钥绝不能进 rc**（rc 在 ramdisk 中 = 明文泄露）
- 正确设计（已派工 sys-guard）：`apd deploy` 将密钥写入固定受保护路径 `/data/adb/sproot/superkey`（0600 / root）→ rc 用**固定路径引用**：`service sproot-apd /data/adb/apd daemon --superkey-file /data/adb/sproot/superkey`，并含 bootloop 次数限制
- 在此之前，UI 不得显示"自启已开启"，应为「已注入 rc（等待 AP 部署完成后生效）」
