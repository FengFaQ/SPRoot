## 2. 本次会话完成的主线

### 2.1 真机首跑 Bug 三连修（已全部进包）
| Bug | 根因 | 修法 |
|---|---|---|
| 修补"成功但无产物" | 引擎成功分支无条件 `remove_all(--workdir)`，而客户端 `--out` 就在 workdir 内 | 显式传 `--workdir` 一律不删；默认 `<out>.work` 才回收（`8a196f0` → `907f5ad` 收口） |
| 密钥 ABI 全链错配 | App 48 字符 / 引擎要 48 / 内核存 47+NUL / 提权须 47 | 全链统一 47；引擎 `embed_key_bytes()` 收口 `key[0:47]+NUL`；`escalation_token()` 改 Result 钉死长度 |
| 旧路径 `superkey` | app 侧 3 处写错（应为 `/data/adb/sproot/key`） | 全部更正（`5ed19c6`） |

### 2.2 UI 全面重构（照抄 KernelSU 的 miuix 实现，人类指令）
- 六页全部重做：主页 / 修补 / 模块 / 授权 / 设置 / 关于
- 修补页从独立 Tab 改为**主页触发的二级页**
- 模块页照 `ModuleMiuix` 全套（搜索/启用禁用分区/详情/FAB/空态/卸载确认）

### 2.3 架构简化：C′ rc 虚拟化（**最大价值项**）
**发现**：APatch 不改 init_boot，靠的是 hook `openat` 把 init 要读的 rc 换成 `/dev/user_init.rc`（原文+追加段）。
**我们的实现**（clean-room，`patch_rc_virtualize.cpp`）：
- hook `__arm64_sys_openat`（`uid==0 + O_RDONLY` 双过滤）
- 原地覆写用户 path 串（28/34 B > 18 B，不改栈指针）
- 洞扫描零硬编码 + 三重断言，报告输出 `caves[]`
- **默认 `--launcher off`，off 时产物与旧引擎逐字节相同**（worktree 对照验证）
**价值**：init_boot 修补整条链（unpack/repack/T-12/AVB）可以退役。

### 2.4 「排除修改」全链路（人类线索驱动的生态集成）
**APatch 实现**（已挖到源码）：kstorage 存 per-uid int + supercall 写入 + **内核文件重定向入口按 uid 短路**。

**我们的落地方案**（借生态，不重写模块系统）：
```
C′ rc 虚拟化 → init post-fs-data 执行 apd post-fs-data
  → apd 遍历模块 post-fs-data.sh
    → NeoZygisk 启 zygiskd（先于 zygote）/ Mountify 建 overlay
      → zygote fork 时注入 → 读 /data/adb/ap/package_config 的 exclude
        → unmount source=="APatch" 的挂载 → 干净 namespace
```

**关键对接事实（全部实测）**：
| 项 | 值 |
|---|---|
| NeoZygisk 读配置 | `/data/adb/ap/package_config`，CSV `pkg,exclude,allow,uid,to_uid,sctx`（**与我们 apd header 一字不差**） |
| NeoZygisk 认 root 方案 | 执行 `apd -V`，取第 2 token 转 i32，要求 ≥ **10762** |
| 卸载判定 | `info.source == "APatch"` |
| Mountify 开关 | `config.sh` 的 `MOUNT_DEVICE_NAME="overlay"` → **必须改成 `"APatch"`** |

**许可证硬筛**：
| 组件 | LICENSE | 内置 |
|---|---|---|
| **Mountify** | **Unlicense（公有领域）** | ✅ 无限制 |
| **NeoZygisk** | GPL-3.0 | ✅ 可（与 AGPL-3.0 兼容） |
| ReZygisk | GPL-3.0 | ✅ 可选 |
| **Zygisk Next** | **无 LICENSE** | ❌ 保留所有权利，不可内置 |

**人类已拍板**：①接受 `apd -V` 伪装 APatch 血统 ②元模块用 **mountify**。

## 3. 代码级关键事实（勿再踩）

### 3.1 SELinux 域约束
```
untrusted_app 只能 exec nativeLibraryDir/libapd.so
/data/adb/apd 只能作为 root-exec 的「目标命令参数」，绝不能当引导器
```
`ApdClient.apdBootstrap()` = 引导器（永远 nativeLibraryDir）
`ApdClient.deployedApd()` = 部署目标（只作参数）

### 3.2 PATH 坑（**已派修但未完成**）
```rust
BINARY_DIR = "/data/adb/ap/bin/"   // 进模块脚本 PATH 的是这个
DAEMON_PATH = "/data/adb/apd"      // apd 实际位置
```
→ NeoZygisk 的 `Command::new("apd")` **找不到** → 判定 `RootImpl::None` → **Zygisk 链静默失效**（且失败是 `debug!` 级别，真机看不见）。
**待修**：①`/data/adb/ap/bin/apd` 建符号链接 ②PATH 加 `/data/adb` ③selftest 加 `apd_in_path` 检查。

### 3.3 zygiskd 启动时机（**已修**）
NeoZygisk 必须在 zygote 前注入。原模板只在 `boot_completed` 启 daemon → **必然错过**。
已加（`4f9c5e9`）：`on post-fs-data` 段 `exec -- /data/adb/apd post-fs-data`（`exec` 是 init 阻塞原语）。
**风险**：`apd post-fs-data` 卡住会拖慢开机 → **apd 侧需该阶段硬超时（待办）**。

### 3.4 密钥 ABI（铁律）
```
App 生成/存储/提权/daemon 文件 = 47 字符无 NUL
调引擎时补成 48（引擎硬要求，内部丢弃第 48 位）
内核内嵌 = key[0:47] + NUL（恰 48 字节，末字节恒 0）
```

### 3.5 「已安装」判定
`installed = (status == ACTIVE)`，且 ACTIVE **只能由真实探测 `selftest stage=daemon_ready`** 产生。
授权操作**绝不**影响安装状态。

## 4. 已明确「不做」的路线

| 路线 | 结论 | 理由 |
|---|---|---|
| **B** 重写模块系统 | 不做 | 等于重写整套挂载（overlay/bind/白名单/原子性） |
| **D** 动态遍历 vfsmount | **降级备选** | 生态已解决（Mountify 预留 `MOUNT_DEVICE_NAME`）；1.2 KB + setresuid hook + 反汇编偏移，成本远高于用现成组件 |
| **G** 轻量 VFS 旁路 | 不做 | 需 hook 10+ syscall，等于重做 VFS 路径解析 |
| **E** 自研 Zygote 注入 | 不做 | 重造 Zygisk 提供者 |
| **C** init hook + usermodehelper | 不做 | init exec 早于 /data 挂载，UMH 必失败；失败=开不了机 |
| **Zygisk Next** | 不能内置 | 无 LICENSE |

**D 路线的分析价值保留**：`docs/NEW-DOC-02 §10` 有反汇编实证（`iterate_mounts` 有 kCFI 检查、`path_umount` 自取 namespace_sem 写锁会死锁、`dget` 不在 kallsyms、结构体偏移清单、`setresuid` 才有 CAP_SYS_ADMIN）。若生态方案失效，这是现成路线图。
